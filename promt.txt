26. QR SECURITY
============================================================

QR token MUST NOT be:

/qr/1

/qr/2

/qr/3

Use cryptographically unpredictable random tokens.

Use:

UUID or SecureRandom.

QR status:

ACTIVE

USED

REVOKED

Optional:

expiresAt

Backend MUST verify:

- Token exists
- Token active
- Token not expired
- User allowed
- Replay protection

Frontend must NOT decide whether QR is valid.

Backend decides.

36. SECURITY REQUIREMENTS
============================================================

Security is a major part of the MVP because the team has two cybersecurity students.

Implement:

- Spring Security
- JWT
- BCrypt
- RBAC
- DTO validation
- Input validation
- Global exception handling
- CORS configuration
- Secure headers where appropriate
- SQL injection protection through JPA
- XSS protection
- Authorization checks
- QR token security
- Replay protection
- Rate limiting where practical
- Audit logging
- Environment variables
- No hard-coded secrets

Important:

Frontend authorization is NOT enough.

Backend must validate every protected operation.

Do not trust:

- userId from request body
- role from frontend
- points from frontend
- product price from frontend
- QR validity from frontend

For order creation:

Price MUST be retrieved from backend/database.

Do not trust price submitted by React.

For gamification:

Points MUST be calculated on backend.

For QR:

Validity MUST be determined by backend.
